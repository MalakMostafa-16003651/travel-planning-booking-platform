**7. Decisions (proposed by AI; student review pending).**
- **Days, activities, budgets and transport costs are embedded** in one Itinerary document. Day number and date are never stored: they come from array position and `startDate`. Reorder, insert and delete therefore cannot leave numbering, dates or city grouping stale. Alternative rejected: separate collections plus a renumbering step, which can partially fail.
- **Optimistic concurrency** makes concurrent edits return 409 instead of losing one of them.
- **Anyone without access gets 404, not 403**, so private itineraries are not revealed to exist (the same approach as flight bookings).
- **Hidden authors are filtered before pagination**: look up the distinct authors of matching itineraries, keep the visible ones, then run the paged query and count with `userId ∈ visible`.
- **Clones** are PRIVATE and independent (new ids, image bytes copied, transport-day links remapped). They carry `clonedFrom` attribution.
- **FX rates**: one hour of cache; on provider failure, cached rates up to 7 days old marked `ratesStale`; otherwise 503. A missing rate returns 422 and an invalid code 400. The API key goes in a bearer header, never in a URL.
- **Images** are checked by their content (magic bytes), not the client's MIME type. They are stored outside the itinerary document.
