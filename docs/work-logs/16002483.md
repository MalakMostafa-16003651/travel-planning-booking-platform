### Understanding the design: questions I asked before accepting changes

Throughout 7–10 November I did not apply generated code without first asking how it worked and why
it was designed that way. The questions below were asked during the sessions (wording formalized,
meaning unchanged), with the explanation I obtained and how it shaped my decisions.

| Question asked | Explanation obtained | Effect on my work |
| --- | --- | --- |
| Why must Person 4's `PendingNotificationsAdapter` be replaced at all? | It only logged "Notification not delivered"; nothing was stored, so GEN-01 was not met. Person 4 used a port (interface + injection token), so only the binding in his module changes, not his service logic. | I designed `notify({ userId, type, message })` to match his port exactly, so the swap required no change to his code. |
| What happens if I build the next step before the previous pull request is merged? | Starting from `develop` would fail to compile because the dependency is missing; starting from the open branch (a stacked branch) works, provided the merge order is respected. | I used stacked branches and stated the merge order in every pull request description. |
| Is the full regression suite mandatory before every pull request? | Not strictly, but it is the only way to prove that changes to shared files such as `app.module.ts` do not break other modules. When only my own folder changes, the related test files plus the integration test are an adequate minimum. | I ran the full suite for changes to shared files, and stated honestly in each PR description which tests were executed. |
| Which values in `.env` are needed, and should they be shared? | Only the team database connection string is required from the team leader; `JWT_SECRET` is generated locally; secrets must never be committed or shared with an AI tool. | I kept all credentials local and requested them privately. |
| Why does the backend fail with `querySrv ECONNREFUSED`, then `bad auth`, then `not allowed to createCollection on test`? | Respectively: the network refused the DNS SRV lookup used by `mongodb+srv://`; the password had been copied incorrectly; the connection string had no database name, so the default `test` database was used. | I switched to the standard `mongodb://` form, corrected the password and added the team database name. |
| Does R3 (a hold committing after hotel deactivation) affect my requirement? | It affects ACC-15, but the fix belongs to the hold transaction: only a write inside that transaction can conflict with the deactivation. My code already deactivates and then releases pending holds. | I raised the issue with the owner (Osama) and recorded it as an open dependency rather than adding a workaround in my module. |
| What exactly does Person 3 need from me, and why does her AI report that it is not ready? | All three items (moderator assignments, the notification method, provider deactivation) were already merged; her local copy was outdated, and the team status matrix still described my requirements as not implemented. | I replied with the exact method names and asked her to synchronize with `develop`. |
| Which teammate request corresponds to which change? | A one-to-one mapping showed that most requests were already satisfied by PRs #68 and #78; only itinerary moderation, report audit recovery and two audit actions remained. | I applied a single focused change set instead of reworking completed features. |
