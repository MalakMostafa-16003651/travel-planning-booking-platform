**3. Decisions.**
- `AuditLogsService.log()` errors propagate, so an admin action never reports
  success without its audit record. Notification failures are logged and do not
  undo an action that already happened, matching Person 4's existing behaviour.
- `NotificationsService.notify()` accepts the plain string types of Person 4's
  `BookingNotificationsPort`, so the flight-booking placeholder can be swapped
  without changing their service code. The swap itself is left to Person 4.
- Suspend, reactivate and provider changes are single conditional updates
  (`findOneAndUpdate` on the expected current state). Two admins acting at once
  produce one change, one audit entry and one set of notifications.
- Suspension only changes `User.status`; Person 1's `AuthSessionsService` already
  rejects non-`ACTIVE` accounts on every request. Admin accounts cannot be
  suspended. Self-deactivated accounts (ACC-12) are not reactivated by an admin.
- Provider deactivation flips `isActive` only; Persons 3, 4 and 5 already enforce it.
  Moderators and customers with Confirmed flight bookings are notified. Hotel
  customers are added once Person 6's hotel bookings exist.
- ACC-13 creates the moderator and its `moderatorassignments` row in one
  transaction, using the exact collection and field names Airlines and Hotels
  already read. The temporary password is hashed with Person 1's exported
  `PasswordService` and `mustChangePassword` is set, so Person 1's restricted
  first-login flow applies. `termsAcceptedAt` is required by the shared User schema
  and is set to the onboarding time; flagged for Person 1.
- Account search escapes regular-expression characters so input is matched literally.
