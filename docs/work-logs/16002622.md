**7. Decisions (proposed by AI; student review pending).**
- **One `RoomAvailability` document per room**, holding `blockedRanges` (this
  module writes) and `bookedRanges` (Person 6's future module writes), instead
  of a document-per-date calendar. A hold/release becomes one conditional
  `updateOne` with an "no overlapping range" filter, the same atomicity
  guarantee `cabininventories` already relies on, without seeding a row per
  night.
- **`:id`-style routes, not `/me`**, unlike Airlines: the PDF lists
  `PATCH /api/hotels/:id` explicitly, and ownership is enforced by comparing
  `:id` to the moderator's assigned `hotelId` (like `getOwnedScheduledFlight`
  does for flights), so Swagger matches the PDF's required endpoint list
  exactly.
- **Room removal is a soft deactivation**, not a hard delete, so a room
  referenced by a past/eventual booking keeps a valid id.
- **`Hotel.isActive`**, mirroring `Airline.isActive`: Person 5 enforces it
  (hidden from search, blocked from new bookings) but does not own the admin
  endpoint that flips it — that is Person 2's ACC-15, still unbuilt on either
  provider.
- **Destination fields resolve through the existing `ReferenceDataService`**
  (`cityId`/`countryCode`), the same catalog Itineraries already uses, instead
  of a free-text destination, so ITN-25's hotel search and `GET /api/hotels/search`
  agree on what a city is.
